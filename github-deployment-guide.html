01準備 GitHub 儲存庫

操作路徑示意圖・非實際截圖
範例名稱：beyblade-market
Visibility：Public
Default branch：main
Create repository
  1. 下載新版部署 ZIP，在 Windows 按右鍵 → 解壓縮全部。
  2. 登入 GitHub，開啟你自己的儲存庫；已有網站的儲存庫可以沿用。
  3. 若還沒有儲存庫，開啟 https://github.com/new；名稱可填 beyblade-market，選 Public，勾選 Add a README file，再按 Create repository。
  4. 以下步驟使用 main 分支。若儲存庫預設分支不是 main，先改成 main，或同步修改工作流程的 branches 設定。

02上傳解壓縮後的檔案

  1. 儲存庫的 Code 頁面 → Add file → Upload files。
  2. 把解壓縮資料夾「裡面的檔案與資料夾」拖進上傳區，再按 Commit changes，提交到 main。
  3. 不要只上傳 ZIP；index.html 必須直接位於儲存庫最外層。
  4. 提交後檢查：index.html、snapshot.json、data、scripts、tests，以及 .github 都有上傳。

03補查 .github 工作流程

操作路徑示意圖・非實際截圖
儲存庫最外層
index.html　＋　snapshot.json
data / scripts / tests
.github → workflows → update-and-deploy.yml
  1. 進入 .github → workflows，確認有 update-and-deploy.yml。
  2. 若 Windows 拖曳上傳漏掉 .github：Code → Add file → Create new file。
  3. 檔名填完整路徑 .github/workflows/update-and-deploy.yml。
  4. 用記事本開啟部署包內同名檔案，複製全部內容貼上，再按 Commit changes，提交到 main。
  5. 網頁版教學下方也附有可複製的完整工作流程。

04開啟網站發佈設定

  1. 點儲存庫上方 Settings；視窗太窄時可能收在「…」選單。
  2. 在左側選單找到 Pages。下一步設定發佈來源。
  3. 官方截圖的儲存庫名稱與你的不同；橘框標示的是按鈕位置。

  4. 暫時還看不到網站網址是正常的；完成第一次成功部署後再回來查看。

06確認 Actions 可以更新資料

操作路徑示意圖・非實際截圖
Settings → Actions → General
Workflow permissions
● Read and write permissions
Save
  1. Settings → Actions → General。
  2. 在 Workflow permissions 選 Read and write permissions，再按 Save。
  3. 部署包本身也已設定 contents: write；這裡一併確認儲存庫設定。
  4. 不需要勾選 Allow GitHub Actions to create and approve pull requests。
  5. 若選項被組織政策鎖住，請儲存庫管理者確認 Actions 與寫入權限。

07找到行情更新工作流程

  1. 回到儲存庫上方，點 Actions。
  2. 左側工作流程清單選 Update market and deploy Pages。
  3. 如果完全找不到這個名稱，回到第 3 步檢查 .github 路徑與 main 分支。

08選擇正確的工作流程

  1. 點左側的工作流程名稱；你的名稱應是 Update market and deploy Pages。
  2. 官方實際截圖使用 GitHub Actions Demo 作為範例，僅對照左側清單的位置。
  3. 若上傳時自動執行曾失敗，先完成 Pages 與權限設定，再手動執行一次。

09第一次手動執行

  1. 右側按 Run workflow → Branch 選 main → 再按綠色 Run workflow。
  2. 點新出現的執行紀錄，等待 publish 工作完成。
  3. 綠色勾勾表示這次成功；若紅色叉叉，展開失敗步驟查看錯誤，再對照後面的排查表。
  4. 官方截圖中的 Browser Tests 是範例名稱；你的頁面會顯示 Update market and deploy Pages。

10打開網站並驗證行情

操作路徑示意圖・非實際截圖
Settings → Pages → Visit site
搜尋陀螺名稱／型號
檢查社團原文連結
網站網址 + snapshot.json → JSON
  1. 回 Settings → Pages，找到 Your site is live at／Visit site，開啟該網址。
  2. 一般專案網址是 https://你的帳號.github.io/儲存庫名稱/；以 Pages 實際提供的網址為準。
  3. 在網站搜尋陀螺名稱或 BX／UX／CX 編號，確認能看到社團貼文與原文連結。
  4. 把網址最後加上 snapshot.json，應看到 JSON 資料，而不是 HTTP 404。
  5. 確認網站的更新時間。每小時第 17 分鐘排程更新，GitHub 可能延後；瀏覽頁面時每 5 分鐘檢查共享資料。

更新方式與資料範圍

近期資料如何判定：近期 7／14／30 天使用文章原始發文日期。沒有可靠發文日期的貼文放在「日期待核對」，不會拿採集時間或成交日期冒充。

目前能收錄的範圍：目前管線搜尋四個社團的公開可索引貼文摘要。私人內容、未被搜尋引擎收錄的最新貼文可能找不到；貼文開價與售出標記也不等於已證實的成交金額。

API Key 是選用設定：可先不填 Key，低量公開搜尋模式已測試可用。若遇額度或頻率限制，可到 Settings → Secrets and variables → Actions → New repository secret，名稱填 FIRECRAWL_API_KEY，值填自己的 Firecrawl Key。

成交統計需要可靠來源：若另外有含原始發文日期與最終成交證據的 HTTPS JSON 來源，可用 MARKET_FEED_URLS 接入。沒有這種來源時，仍可瀏覽社團買賣貼文。

排程長期維護：GitHub 排程不是準點保證。公開儲存庫長時間無活動可能停用排程；若 Actions 顯示停用提示，重新啟用，再手動 Run workflow。

故障排查

看到的問題處理方式
snapshot.json 回傳 404確認上傳完整部署包、Pages Source 是 GitHub Actions，且最後一次部署成功。檢查網址中的儲存庫名稱與大小寫。
Actions 沒有行情工作流程確認 .github/workflows/update-and-deploy.yml 在 main 分支；不要放在額外的外層資料夾。
git push 出現 403／permission denied檢查第 6 步、工作流程 contents: write，以及分支保護規則是否允許 bot 更新。
configure-pages／deploy-pages 失敗先設定 Pages Source 為 GitHub Actions；回 Actions 手動再執行一次。
搜尋回 429／quota／unauthorized查看採集步驟紀錄；可加入有效 FIRECRAWL_API_KEY。既有資料會保留，需注意網站最後成功更新時間。
網站有資料但沒有最新貼文公開搜尋有索引延遲；檢查原文與發文日期。需要完整近期收錄時，必須另接可取得貼文的可靠資料來源。

漏傳 .github？直接複製工作流程

新建檔案路徑：.github/workflows/update-and-deploy.yml

展開工作流程內容
name: Update market and deploy Pages
on:
  schedule:
    - cron: '17 * * * *'
  workflow_dispatch:
  push:
    branches: [main]
    paths-ignore: ['data/snapshot.json', 'snapshot.json', 'README.md', 'tests/**']
permissions:
  contents: write
  pages: write
  id-token: write
concurrency:
  group: market-pages
  cancel-in-progress: false
jobs:
  publish:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    environment:
      name: github-pages
      url: ${{ steps.deploy.outputs.page_url }}
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-python@v6
        with:
          python-version: '3.12'
      - uses: actions/setup-node@v6
        with:
          node-version: '24'
      - name: Test frontend
        run: node tests/frontend.cjs
      - name: Test collector
        run: python -m unittest discover -s tests -v
      - name: Collect public references and dated market feed
        env:
          FIRECRAWL_API_KEY: ${{ secrets.FIRECRAWL_API_KEY }}
          MARKET_FEED_URLS: ${{ secrets.MARKET_FEED_URLS }}
        run: python scripts/update_market.py
      - name: Save shared data history
        run: |
          git config user.name 'github-actions[bot]'
          git config user.email '41898282+github-actions[bot]@users.noreply.github.com'
          git add data/snapshot.json snapshot.json
          if ! git diff --cached --quiet; then
            git commit -m 'Update shared market snapshot [skip ci]'
            git push
          fi
      - uses: actions/configure-pages@v5
      - name: Prepare public site
        run: |
          mkdir -p _site
          cp index.html _site/index.html
          cp data/snapshot.json _site/snapshot.json
          touch _site/.nojekyll
      - uses: actions/upload-pages-artifact@v4
        with:
          path: _site
      - uses: actions/deploy-pages@v4
        id: deploy

scripts、tests、data 等資料夾仍需一併上傳；單獨貼 YAML 無法完成部署。
